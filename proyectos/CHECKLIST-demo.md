# Checklist de demo

Usa este archivo antes de presentar. Si algo no está listo, dilo en la demo; no lo escondas.

## Antes de mostrar

- [ ] El problema cabe en una frase.
- [ ] Está claro quién usa el sistema.
- [ ] Dentro y fuera de alcance están escritos.
- [ ] La definición de terminado se puede verificar sin preguntarle al modelo.
- [ ] La línea base dice cómo se midió o declara que todavía falta.

## Durante la demo

- [ ] Muestro una entrada normal.
- [ ] Muestro una entrada límite o adversarial.
- [ ] Señalo qué resolvió un `if`.
- [ ] Señalo dónde intervino IA y qué salida estructurada produjo.
- [ ] Muestro qué pasa cuando la salida no valida o la confianza es baja.
- [ ] Muestro la comparación contra la salida esperada.
- [ ] Digo la tasa como `aciertos/total`, no como “se ve bien”.

## Gobernanza

- [ ] No aparece ninguna credencial.
- [ ] Sé qué permisos necesita cada integración.
- [ ] La acción irreversible tiene aprobación humana o está explícitamente fuera de alcance.
- [ ] Sé cómo me entero de una falla.
- [ ] Hay un tope de gasto o una razón documentada para no usar API de pago.

## Handoff

- [ ] Otra persona puede encontrar el punto de entrada.
- [ ] Otra persona sabe cómo ejecutar una prueba.
- [ ] Otra persona sabe qué hacer si falla.
- [ ] Las limitaciones están escritas.
- [ ] El README no depende de conocimiento que solo existe en mi cabeza.
